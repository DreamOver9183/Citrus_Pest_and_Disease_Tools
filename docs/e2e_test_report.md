# End-to-End 測試執行報告

專案有兩支端到端測試，都需要後端已在執行，且在缺少素材時**優雅跳過並回傳 0**（`LocalLibrary/` 與 `Datasets/` 都不進版控，不保證存在）。

| 腳本 | 定位 | 素材來源 |
|---|---|---|
| `e2e_tests/e2e_local_library.py` | **主力**，16 個階段涵蓋全系統 | `LocalLibrary/` 內的真實檔案 |
| `e2e_tests/e2e_test.py` | 早期的上傳流程煙霧測試 | `E2E_ASSETS_DIR` 指向的特定佈局素材夾 |

## 設計原則：斷言必須對照可獨立驗證的事實

這是本測試最重要的一條規則。**不能拿後端的一個欄位去比對後端的另一個欄位**——那只證明系統自洽，不證明它正確。因此：

- 資料集的影像／標註數，直接數 ZIP 內的成員來對答案。
- 推論結果，對照該圖真實標註檔裡的類別索引。
- 權重登錄簿的身分，測試腳本**自己**對權重檔算一次 SHA-256。
- 登錄簿存的超參數，測試腳本**自己** parse 一次 `args.yaml` 逐鍵比對。
- Micro-Accuracy，用存進資料庫的 TP/FP/FN 三個計數重算一次，再用另一條完全不同的代數路徑（`1/(1/P + 1/R − 1)`）交叉驗算。

### 階段 13 的關鍵回歸

系統原本只保留 `epochs` / `optimizer` / `model` 三個鍵，其餘在解析當下就丟棄。實測本專案的 `args.yaml` 有 **116 個鍵**——被丟掉的 113 項（`lr0`、`mosaic`、`patience`、各項 augment…）正是消融研究要比較的東西。測試明確斷言「超參數不只保留三項」，防止這個缺陷回歸。

### 階段 14 的三重驗算

```
TP=777  FP=1,718  FN=1,523   Micro-Accuracy=0.1934   （conf ≥ 0.25, IoU ≥ 0.45）
```

1. **與 job 完全相等**：登錄簿的 `map50` / `map50_95` / `precision` / `recall` 與評估 job 的值逐項相等（0.3003 / 0.1071 / 0.3577 / 0.3873）。
2. **公式重算**：`TP/(TP+FP+FN) = 777/4018 = 0.1934` ✓
3. **代數恆等式**：`1/(1/P + 1/R − 1)` 以微平均 P=0.3114、R=0.3378 代入亦得 **0.1934** ✓
   兩條算式完全不同，任何一邊寫錯（例如 FP/FN 的行列取反）都會立刻不一致。
4. **硬不變量**：`TP + FN = 777 + 1,523 = 2,300`，等於腳本自己數出的該 split 標註框總數 **2,300** ✓

> **這條不變量抓到過一個真實的認知落差。** 第一次執行是 2,300 vs 2,302，差 2。追下去發現 v5 資料集的 `test_0175.txt` 有 4 列但只有 2 列相異，而 ultralytics 在載入標註時會做 `np.unique(lb, axis=0)`。**不變量與實作都是對的，錯的是測試的數法**——腳本已改為去重後計數，並把原因寫進註解。

## 這次改版中 E2E 抓到、單元測試沒抓到的缺陷

權重登錄簿有三個寫入接點。實作時完成了 `sessions.py` 的兩條上傳路徑與 `evaluation_service`，**漏掉了 `library_scanner.register()`**——也就是 LocalLibrary 載入模型的那條路徑。

349 項單元測試全數通過（它們直接測 service 層，該層是好的），但 E2E 立刻紅：

```
[FAIL] 登錄簿有回傳權重清單  (0 筆)
[FAIL] 權重已入帳且雜湊相符：YOLO26n_P2_Citrus_MuSGD_v8（本機）
[FAIL] 評估結果已寫進登錄簿
```

這正是「E2E 必須從外部觀察真實流程」的價值：單元測試證明零件對，E2E 證明**線接上了**。

## 執行方式

```bash
# 主力測試（後端需已在執行；Docker 或本機皆可）
python e2e_tests/e2e_local_library.py
```

環境變數：

| 變數 | 預設 | 說明 |
|---|---|---|
| `E2E_BASE_URL` | `http://localhost:8000/api` | 後端位址 |
| `E2E_LIBRARY_DIR` | 由檔案位置推導 | 主機端 `LocalLibrary/` 路徑 |
| `E2E_SKIP_TFLITE` | 未設定 | 設為 `1` 可略過耗時約 100 秒的 TFLite 匯出 |

早期的上傳流程煙霧測試：

```bash
E2E_ASSETS_DIR=<path> python e2e_tests/e2e_test.py
```

> Windows 終端機預設編碼為 cp950，直接執行時中文與符號可能顯示為亂碼。加上 `PYTHONIOENCODING=utf-8` 即可正常顯示，這不影響測試有效性。
