## 一、 專案背景與特徵工程痛點分析
在現代精準農業與智慧巡檢應用中，建構一套部署於邊緣裝置（Edge Devices，如智慧型手機、田間微型相機）的即時病蟲害偵測系統具有極高的實用價值。本專案旨在利用最新一代的目標偵測模型 **YOLO26-nano**（整合高解析度特徵圖之 **P2 檢測層**），實現對柑橘常見之 $2$ 種健康對照品種、$4$ 種病害與 $4$ 種蟲害的精準識別。

然而，在進入深度學習模型訓練（Model Training）前，原始影像與標註資料面臨多項極具挑戰性的特徵工程痛點：

1. **極端的類別不平衡（Extreme Class Imbalance）：** 強勢類別（如介殼蟲、蚜蟲本體）原始樣本高達 $800$ 至 $1,100$ 張，而弱勢特徵類別（如蚜蟲造成的葉片傷害 `P_AP_LD`）在經過精準篩選後僅剩 $27$ 張。若直接投入訓練，模型將產生嚴重的類別偏見（Class Bias），導致對弱勢類別的召回率（Recall）近乎為 $0$。
    
2. **多源標註格式不一與 Class ID 衝突：** 原始資料集取自 Roboflow 平台之多個獨立專案，合併後各子資料夾的標籤檔案（`.txt`）存在嚴重的 Class ID 重疊衝突（如多個檔案均將自身類別標註為 $0$）。
    
3. **微小物件偵測（Small Object Detection）挑戰：** 蚜蟲本體（`P_AP`）與薊馬本體（`P_TP`）在實際田間影像中，往往僅佔據數個至數十個像素（Pixels）。如何進行影像增強而不破壞這些微小物體的邊界框（Bounding Box，簡稱 bbox）完整性，是提升模型在 P2 檢測層特徵提取能力的關鍵技術。
    

為了克服上述瓶頸，本團隊規劃並落實了一套標準化資料工程流水線（Data Engineering Pipeline），完整流程包含：**前置配對校對** $\rightarrow$ **類別整併與成對命名標準化** $\rightarrow$ $80\% / 10\% / 10\%$ **學術分割** $\rightarrow$ **全域標籤 ID 強制修正對齊** $\rightarrow$ **基於過擬合防禦之動態過採樣影像增強**。以下為本資料集標準化專案的最終執行報告。

### 2. 「蟲體」與「葉片傷害」之雙軌診斷機制與細緻化命名判定

在農業病蟲害臨床實務中，害蟲活體常因移動或施藥防治後飛離，但其留下的典型物理傷害特徵（食痕、褪色、組織壞死）是診斷的唯一依據。因此，本專案不採取單一合併，而是堅持維持「蟲體本身」與「傷害痕跡」的雙軌判定架構。

在重新命名階段，為了克服「同一張影像同時包含蟲體與傷害」之語意衝突，重新命名腳本在 local 端讀取了每一張原始標註檔（`.txt`）之 Class ID 內容，執行以下判定：

- **蚜蟲類別判定：**
    
    - 若偵測標註檔內僅包含 Class $0$（`Aphid` 蟲體標註）或為空標註，統一命名為 `P_AP_`。
        
    - 若偵測標註檔內一旦出現 Class $1$（`Aphid_Leaf_Damage` 傷害標註），無論是否存在蟲體，強制歸類為 `P_AP_LD_`。此舉可避免將具備大面積葉片皺縮特徵的影像誤歸類為單純蟲體，確保大尺度的幾何特徵被精準捕捉。
        
- **薊馬類別判定：**
    
    - 若標註檔僅含 Class $0$（`Thysanoptera` 蟲體），命名為 `P_TP_`。
        
    - 若標註檔出現 Class $1$（`thirps_leaf_damage` 銀白色食痕傷害），則命名為 `P_TP_LD_`。

## 三、 學術級資料集拆分架構（Dataset Split）

為了徹底杜減影像特徵工程中極具毀滅性的「資料洩漏（Data Leakage）」**問題，我們嚴格禁止「先做影像增強再進行分割」的錯誤流向，而是採取**「先分割資料集，再對訓練集進行局部定向增強」之黃金標準規範。

### 1. YOLO 標準目錄結構實踐

專案工作區被重新調整為標準的 YOLO 目錄結構，以便在後續訓練中直接透過 `data.yaml` 進行動態路徑對齊：


- **測試集（Test Set -** $10\%$**）：** $440$ 組

## 五、 動態過採樣與防禦型影像增強

為了解決類別極度不平衡問題，本專案引進了「動態過採樣與過擬合防禦機制」。我們不使用簡單粗暴的固定倍率（如全體乘 $2$ 倍），因為這會導致強勢類別（如介殼蟲）樣本膨脹至兩千張以上，耗費巨大運算資源，卻無法顯著提升精度；同時也會讓僅有 $27$ 張的蚜蟲傷害類別因過度重複而產生嚴重的局部過擬合。

### 1. 分層定量擴充策略與目標

本專案將增強目標定為：**將大多數類別在訓練集（Train Set）中的樣本張數拉平至** $800$ **至** $1,000$ **張的「黃金均衡區間」**。

- **強勢類別防禦：** 介殼蟲（`P_SI_`）在 train 中已有 $895$ 張，設定為 $1$ 倍（不進行任何增強），直接保留原圖特徵。
    
- **一般與中度弱勢類別追趕：** 依原始張數動態設定 $4$ 至 $6$ 倍的增強率（如健康椪柑 $158$ 張 $\times 5.1 \approx 800$ 張，煤煙病 $261$ 張 $\times 4 \approx 1,044$ 張）。
    
- **極度弱勢類別防禦保護：** 蚜蟲傷害（`P_AP_LD_`）原始僅 $28$ 張，若強行拉平至 $1000$ 張會導致 $35$ 倍的極端重疊，誘發嚴重的過擬合。本專案將其增強倍率硬性限制為 $14$ **倍**，使其數量收在 $392$ **張的妥協安全水位**。

### 3. Albumentations 增強 Pipeline 核心設計與參數技術分析

本專案使用 `Albumentations` 影像增強套件，並針對含有邊界框標註之病蟲害樣本與無標註（空檔案）之健康葉片對照樣本，分別量身打造了兩組核心 Pipelines，其精細參數調校與背後之電腦視覺原理說明如下：

#### A. 核心增強管線（`FULL_TRANSFORM`）

專門用於含有病蟲害邊界框（Bounding Box）的圖片，透過物理形變、採光模擬與相機雜訊引入，大幅提升模型的泛化能力：

```
import albumentations as A

FULL_TRANSFORM = A.Compose([
    # 1. 幾何變換 (幾何翻轉與旋轉)
    A.HorizontalFlip(p=0.5),
    A.VerticalFlip(p=0.5),
    A.RandomRotate90(p=0.5),
    A.ShiftScaleRotate(
        shift_limit=0.05, 
        scale_limit=0.05, 
        rotate_limit=15, 
        border_mode=0, 
        value=0, 
        p=0.5
    ),
    
    # 2. 環境光強與色調偏置模擬
    A.RandomBrightnessContrast(
        brightness_limit=0.15, 
        contrast_limit=0.15, 
        p=0.5
    ),
    A.HueSaturationValue(
        hue_shift_limit=8, 
        sat_shift_limit=12, 
        val_shift_limit=10, 
        p=0.3
    ),
    
    # 3. 邊緣運算手機雜訊模擬 (手震模糊)
    A.OneOf([
        A.Blur(blur_limit=3, p=1.0),
        A.GaussianBlur(blur_limit=3, p=1.0)
    ], p=0.2)
], bbox_params=A.BboxParams(
    format='yolo', 
    label_fields=['class_labels'], 
    min_visibility=0.25,
    check_each_transform=True
))
```

##### ⚙️ `FULL_TRANSFORM` 算子與精準參數深度剖析：

- **`HorizontalFlip(p=0.5)` 與 `VerticalFlip(p=0.5)`**
    
    - **算子原理**：將影像分別繞著垂直 Y 軸（水平翻轉）與水平 X 軸（垂直翻轉）進行鏡像對稱變換。
        
    - **參數說明**：機率參數 $p=0.5$，代表每次執行時有 $50\%$ 的機率會被套用。
        
    - **農業防禦與特徵物理意義**：果園中的柑橘葉片與害蟲不具備固定的重力方向（可能向上、向下或左右橫向生長）。翻轉算子在不改動任何像素特徵的前提下，可使影像之空間分佈多樣性擴增至原本的 $4$ 倍，能有效訓練 YOLO26 學習「非方向依賴型」特徵。
        
- **`RandomRotate90(p=0.5)`**
    
    - **算子原理**：以 $0.5$ 的機率，隨機對影像進行 $90^\circ$、$180^\circ$ 或 $270^\circ$ 的直角旋轉。
        
    - **核心技術保護**：在目標偵測中，任意角度旋轉會導致原先「平行於軸向」的 YOLO Bounding Box 發生「對角擴張（Bounding Box Inflation）」**（即旋轉後的框會將大片無病蟲害的背景葉面框進去，導致模型學習到多餘雜訊）。直角旋轉是唯一能進行幾何旋轉，而**百分之百不改變 Bounding Box 緊密度與高寬比例的安全旋轉算子。
        
- **`ShiftScaleRotate(shift_limit=0.05, scale_limit=0.05, rotate_limit=15, border_mode=0, value=0, p=0.5)`**
    
    - **`shift_limit=0.05`（平移限制）**：限制影像在水平與垂直方向的最大平移位移量為影像寬高之 $\pm 5\%$。此參數能模擬拍攝時目標物偏離中央的「不完美構圖」，訓練模型的空間位移不變性（Translation Invariance）。
        
    - **`scale_limit=0.05`（縮放限制）**：限制縮放倍率落於 $[0.95, 1.05]$ 區間（縮小或放大最大 $5\%$）。這是一個針對微小物件（如蚜蟲、薊馬）特別採取的**極度保守參數**。若縮小比例過大（例如 `scale_limit=0.3`），原本在 P2 檢測層特徵圖上就只有 $4 \times 4$ 像素點的薊馬會直接縮小到低於 $1$ 像素而「完全消失」，進而破壞 YOLO 的反向傳播梯度。
        
    - **`rotate_limit=15`（任意角度旋轉限制）**：限制影像僅能在 $[-15^\circ, 15^\circ]$ 的窄範圍內隨機傾斜。這同樣是為了**將 Bounding Box 的對角擴張程度壓到最低限度**，避免 Bounding Box 座標過度虛胖而干擾非極大值抑制（NMS）的推論表現。
        
    - **`border_mode=0` (`cv2.BORDER_CONSTANT`) 且 `value=0`**：平移與任意旋轉後，畫面邊緣會產生暴露的空白空白區。設定 `border_mode=0` 代表使用 OpenCV 的常數填充機制（BORDER_CONSTANT），並指定顏色 `value=0`（純黑）。相較於邊緣像素拉伸（REPLICATE）或鏡像反射（REFLECT），**純黑填充是 YOLO 官方最推薦的填充模式**，能確保模型能一眼看懂邊界，不會去錯誤提取邊緣拉伸產生的條紋特徵。
        
- **`RandomBrightnessContrast(brightness_limit=0.15, contrast_limit=0.15, p=0.5)`**
    
    - **算子原理**：隨機在 $[-15\%, +15\%]$ 的區間內增減影像亮度與對比度。
        
    - **農業防禦與特徵物理意義**：真實田間採光受雲層遮擋、太陽直射或果樹陰影遮蔽影響。此算子能模擬「曝光過度（Sunny Overexposure）」與「曝光不足（Cloudy Underexposure）」的極端情境，避免 YOLO 在陰影處漏檢。
        
- **`HueSaturationValue(hue_shift_limit=8, sat_shift_limit=12, val_shift_limit=10, p=0.3)`**
    
    - **算子原理**：將影像從常規 RGB 色彩空間轉換至 HSV 色彩空間，並對色相（Hue）、飽和度（Saturation）、明度（Value）三個通道進行偏移調校。
        
    - **`hue_shift_limit=8`**：在最大 $180$ 度的 H 通道中，限制隨機色相偏置在 $\pm 8$ 階內。這是一個精心設計的**物理閾值**：它能微幅改變柑橘葉片的綠色漸層（例如老葉呈現深綠色，新芽呈現黃綠色），卻**絕對不會跨越光學色彩極限**，避免出現不符合植物生理學的「藍色葉片」或「紫色害蟲」，維持資料特徵的真實性。
        
    - **`sat_shift_limit=12`**：改變飽和度上限為 $\pm 12$ 階，模擬不同大氣濕度與相機感光元件色彩鮮豔度的落差。
        
    - **`val_shift_limit=10`**：改變明度通道 $\pm 10$ 階，協同亮度算子，共同在 HSV 色彩維度建立穩健的光照模型。
        
- **`OneOf([Blur(blur_limit=3, p=1.0), GaussianBlur(blur_limit=3, p=1.0)], p=0.2)`**
    
    - **`OneOf` 機制**：從指定的「均勻模糊（Blur）」與「高斯模糊（GaussianBlur）」中，隨機挑選且僅執行其中一種，套用機率為 $20\%$。
        
    - **`blur_limit=3`**：限制平滑核心大小（Kernel Size）最大僅能為 $3 \times 3$。
        
    - **邊邊運算技術痛點防禦**：當農民手持智慧型手機靠近葉片拍攝蚜蟲（約 $15$ 到 $20$ 公分）時，手機感光元件極易因對焦鏡頭微震或手部抖動產生「手震模糊（Motion Blur）」。若模型訓練資料皆為腳架拍攝的完美清晰圖片，部署在邊緣端實測時一有晃動便會瞬間丟失特徵。套用限制大小為 $3$ 的微模糊，能強迫 P2 特徵金字塔在「邊緣像素模糊」時，依然能依靠害蟲的群聚質地特徵（Texture）完成高置信度召回。
        

#### B. 邊界框安全保護與座標重構設定（`bbox_params`）

在目標偵測中，影像歷經幾何裁剪、平移與旋轉後，其對應的標註框（Bounding Box）必須套用極嚴格的過濾演算法，以防訓練出破壞學習梯度的「垃圾標籤（Noisy Labels）」：

```
bbox_params=A.BboxParams(
    format='yolo', 
    label_fields=['class_labels'], 
    min_visibility=0.25,
    check_each_transform=True
)
```

##### ⚙️ `bbox_params` 的安全控制邏輯：

- **`format='yolo'`**：指定標註輸入為 normalized $4$-dimensional 座標向量 $(x_{\text{center}}, y_{\text{center}}, \text{width}, \text{height})$，數值皆縮放於 $[0, 1]$ 區間內。
    
- **`min_visibility=0.25`（最小可視面積閾值）**：這是本專案的核心安全閥。在幾何形變（如平移、旋轉）中，若某個病斑或害蟲 Bounding Box 的部分區域被移出畫面邊緣，導致其**留在影像內部的面積低於原先完整面積的** $25\%$ 時，Albumentations 會在增強後的標註檔（`.txt`）中**自動將此一 bbox 徹底剔除**。
    
    - _技術原因_：如果將只剩 $5\%$ 部分殘餘、完全不具備蚜蟲輪廓特徵的邊界框也送去訓練，YOLO 將被迫去強記該邊緣背景像素，產生嚴重的特徵誤導（Feature Pollution）。
        
- **`check_each_transform=True`**：在 Pipeline 的每一個串聯步驟後，立即進行 bbox 合法性（邊界是否越界、寬高是否大於零）的遞迴檢查。一旦在中間步驟發現異常，立即丟棄並重新嘗試生成，實現自動化影像增強階段的「零髒資料（Zero Dirty Data）」過濾機制。
    

#### C. 健康植株背景增強管線（`EMPTY_FULL_TRANSFORM`）

對於健康椪柑（`H_PK_`）與健康茂谷柑（`H_MC_`）的訓練集影像，其 `.txt` 檔案為空標註（代表該影像中沒有任何病蟲害，屬於負樣本，用於降低 YOLO 的假陽性/誤判率）。

如果直接將這群無標註的影像丟進上面的 `FULL_TRANSFORM` 管線，Albumentations 的 `bbox_params` 內部機制在檢索不到 `class_labels` 與任何 Bounding Box 時會**觸發運行期崩潰（RuntimeException）**。

因此，本專案為健康背景樣本單獨定義了 **`EMPTY_FULL_TRANSFORM`**：

```
# 僅繼承影像變換，徹底移除 bbox 相關參數與 label 對齊傳遞
EMPTY_FULL_TRANSFORM = A.Compose([
    A.HorizontalFlip(p=0.5),
    A.VerticalFlip(p=0.5),
    A.RandomRotate90(p=0.5),
    A.ShiftScaleRotate(
        shift_limit=0.05, 
        scale_limit=0.05, 
        rotate_limit=15, 
        border_mode=0, 
        value=0, 
        p=0.5
    ),
    A.RandomBrightnessContrast(
        brightness_limit=0.15, 
        contrast_limit=0.15, 
        p=0.5
    ),
    A.HueSaturationValue(
        hue_shift_limit=8, 
        sat_shift_limit=12, 
        val_shift_limit=10, 
        p=0.3
    ),
    A.OneOf([
        A.Blur(blur_limit=3, p=1.0),
        A.GaussianBlur(blur_limit=3, p=1.0)
    ], p=0.2)
])  # 沒有宣告 bbox_params，確保空標註樣本可流暢增強不卡死
```

這個無標註背景影像管線，讓健康的柑橘葉片影像在經歷了手震模糊、高低對比色差後，依舊能作為高質量的背景對照組（Negative Background），大幅抑制 YOLO26 nano 模型在田間容易把一般葉子反光、正常疤痕誤判為病蟲害的敏感通病。
